# 跨年自动归档 — 设计文档

日期：2026-10-17
状态：已通过设计评审，待实现

## 1. 背景与问题

本项目用 12 张 MySQL 表 `table_01` ~ `table_12` 按月循环存放消费记录，收入表
`income_records` 也用 `month` 字段按月存放。两者都**没有年份字段**。

后果：跨年后同一个月的表会被新数据覆盖，上一年该月的历史数据无声丢失，无法找回。

## 2. 目标与成功标准

- 跨年时，旧年度的数据被导出为 Excel 文件保留下来，不丢失。
- 文件名按「年-月」命名，集中放在项目的 `records/` 目录。
- 新年度从空表重新开始。
- 成功标准：跨年后能在 `records/` 下找到类似 `2026-01.xlsx`、`2026-income.xlsx`
  的文件，且内容与旧数据一致；对应数据库表已清空。

## 3. 非目标（YAGNI）

- 不支持「同一年内多年度数据长期共存」（那是给表加 `year` 列的方案，已排除）。
- 不做归档文件的 Web 浏览/管理界面，本次只落盘。
- 不改变现有浏览器端 Excel 导出功能。
- 不做归档定时任务/后台线程。

## 4. 判定机制：年份标记文件

程序无法从表内容判断数据年份，因此引入一个持久标记：

- 路径：`records/.current_year`
- 内容：一行整数年份，表示「当前这套表里的数据属于哪一年」。
- 首次运行（无标记）：只写入当前年份，**不归档**。
- 启动时判定：`标记年份 < 当前年份` → 判定为跨年 → 执行归档。

## 5. 触发时机（方案 A：启动时统一检查）

统一入口 `Archiver.ensureRollover()`，幂等，可安全重复调用。调用点：

1. `The_main.main()` 启动后、`WebServer.start()` 之前 —— 主触发点。
2. Web 端消费/收入写入处理，写入前 —— 防止程序长跑跨年不重启。
3. 控制台版 `The_main.saveConsumption()`，写入前 —— 同上。

未跨年时 `ensureRollover()` 立即返回，开销极小。

## 6. 归档产物

目录：`records/`（不存在则创建）。

### 6.1 消费表（12 张）

- 对 `table_MM`（MM = 01..12）：**仅当表内有记录**时才导出。
- 文件名：`records/<旧年>-<MM>.xlsx`，例如 `records/2026-01.xlsx`。
- 工作表名「消费」，列：序号 / 日期 / 商品 / 价格 / 类型。
  - 类型由 `num_1` 映射：`1 → 日常`，`2 → 特殊`。
- 末尾追加一行合计（`合计` + 价格总和）。

### 6.2 收入表

- 对 `income_records`：**仅当表内有记录**时才导出。
- 文件名：`records/<旧年>-income.xlsx`。
- 工作表名「收入」，列：序号 / 月份 / 日期 / 金额 / 说明。

## 7. 处理顺序与失败安全

严格顺序，任一步失败即中止：

1. 逐表导出 Excel 到 `records/`。
2. 全部导出成功后，清空对应表（`DELETE FROM ...`）。
3. 全部清空成功后，把标记文件的年份更新为当前年。

失败处理：
- 导出或清空抛异常 → 中止本次归档，**不清表、不更新标记**，打印错误，下次启动重试。
- 表已无记录 → 跳过，不产生空文件。
- 目标文件已存在 → 直接覆盖（此时表中仍是同一批数据）。

## 8. 路径基准与限制

- 以 `System.getProperty("user.dir")`（IDEA 运行即项目根目录）为基准拼接 `records/`。
- 限制：若日后打包成 jar 并从其他工作目录启动，`records/` 会落在那个目录下。
  本设计接受该限制并在此注明。

## 9. 组件与接口

新增 `src/function/Archiver.java`：

- `public static void ensureRollover()` —— 唯一对外入口，幂等。
- 内部（便于测试的纯函数与副作用分离）：
  - `static boolean shouldArchive(int markerYear, int currentYear)` —— 纯判定。
  - `static List<String[]>` 构造行数据的方法 —— 纯数据构造。
  - 私有：读/写标记、`archiveConsumption(...)`、`archiveIncome(...)`、清表。

依赖：`One`（连接）、`Date_time`、Apache POI（`poi-5.2.5` / `poi-ooxml-5.2.5`，已在 `lib/`，当前未被任何代码引用）。

## 10. 测试策略

- 纯函数单测：`shouldArchive`、Excel 行数据构造（不依赖 DB）。
- DB 场景手工验证：
  1. 把 `records/.current_year` 改成去年。
  2. 往 `table_01` 与 `income_records` 各插几条。
  3. 启动程序。
  4. 检查 `records/<去年>-01.xlsx`、`records/<去年>-income.xlsx` 内容正确；
     `table_01`、`income_records` 已清空；标记更新为当前年。
  5. 再次启动，确认幂等（不再归档、无重复文件）。

## 11. 风险与限制

- 多年度空档（如标记年为 2024、当前 2026）：按标记年归档为 `2024-XX`，属近似处理，可接受。
- POI 首次使用需确认 `lib/` 依赖已加入项目库，否则编译失败。
- 归档判断完全依赖标记文件；标记文件被误删会导致无法判定年份（首次运行逻辑会重置标记，旧数据可能被当作当前年数据）。文档中注明不要手工删除该文件。
